## Questions from the brief

| Question | Answer |
|---|---|
| Can any process an agent controls write outside its role's writable roots? | Not under the default policy: the §12 escapes (absolute path, `..`, symlink, rename, `mkdir`, temp file, Python `open()`, redirect, another worktree) fail with `EROFS` and the host is byte-identical (tests; E0). Bind order is right: host read-only, project visible, runs hidden, writable roots, read-only re-binds, masks. The one way out is the operator's own `containment.writable`: a root over the project or `/tmp` is accepted, passes the self-test, and makes control state, the evidence directory and other runs' harness state writable (F1). |
| Is the real git metadata truly immutable from inside, so host-side git can never be redirected? | Yes. The common `.git`, the worktree's `.git/worktrees/<id>/` (`HEAD`, `index`, `commondir`, `gitdir`, the AEW marker) and the `.git` pointer file are re-bound read-only after every writable bind, including operator roots (E1 shows `update-ref` still refused with the project root writable). The agent's git works on a private index and object store; the engine's host-side operations read the real index, refs and pointer, which the agent cannot alter. Hooks are read-only too, which also closes the Windows-only hook vector noted in the area 2 review. |
| Does the launch self-test prove what it claims, or can a broken layout pass it? | It proves what it probes: one sentinel next to the workspace, the writable roots, and the protected git paths. A layout broken by an operator root over the project or `/tmp` passes it (F1), because none of those probes lands in the newly writable region. The sentinel does catch a root over `$HOME` or the workspaces root (E3). |
| Fail-closed: any path where a run starts uncontained under the default policy? | None on Linux. The supervisor's tree requires a layout until `_contain` installs one; `establish` raises under `required` on a missing bubblewrap, disabled user namespaces, a role without a layout, a write role outside a Ticket scope, or a failed self-test, and the run ends `launch_failed` before any harness process exists. Checks go through the same tree. One wording gap: `required` is silently `allow_weaker` on any non-Linux POSIX platform, not only Windows (note 2). |
| Process ownership: can a descendant survive stop or the supervisor's death? Is the pid translation sound? | No descendant survives: every process is in the run's PID namespace, `kill()` ends bubblewrap's host process, `--die-with-parent` takes the sandbox when the supervisor dies, and the tests cover `setsid`, double fork, `SIGKILL` of bubblewrap and `SIGKILL` of the owner. The namespace-pid translation is not sound as a function: with no match it returns the queried pid as if it were a host pid, and it matches only the innermost `NSpid`, so a pid the agent reports for a process in a nested namespace is misattributed (F2). The test helper that uses it subtracts the raw pid, so today's E13 evidence is not wrong. |
| Are the labels truthful? | Yes. `os_readonly_roots` is documented and reported as filesystem integrity only, the host stays readable apart from masks and other runs, `network: not_provided` on every label, `process_ownership` names the mechanism actually used, old string records normalize to `workdir_separation_only`, and the server-environment residual is stated and asserted by a test. The label is only as truthful as the self-test behind it, which is F1's point. |

## Findings

### F1. Major — an operator `containment.writable` root is not checked against what containment protects, and the self-test cannot see the overlap

- **Where:** `src/aew/harness/containment/layout.py:212-218` (operator roots are appended to `writable` after only an `isdir` check), `layout.py:83-101` (`bwrap_argv`: writable binds come after the project bind and the runs tmpfs, so a root that covers them shadows both), `src/aew/harness/containment/probe.py:61-101` (the self-test probes one sentinel next to the workspace, the writable roots and the git `protected` paths; nothing under `.aew`, the runs directory or the host `/tmp`), `src/aew/harness/containment/__init__.py:84-98` (the passing self-test yields the `os_readonly_roots` label).
- **Guarantee:** ADR-0009 M4-B "A contained process can write only its role's writable roots"; "one run never reads another's harness state"; "The bridge socket always lives under `/tmp` ... no sandbox sees another run's socket"; the design's invariant 10 (`FALSE_CONTAINMENT_CLAIM`) and the brief's "operator-declared writable roots overlapping protected paths".
- **Scenario (E1):** the operator sets `containment.writable: [~/project]` meaning to let runs write a build directory. `for_run` accepts it, `probe.self_test` passes, and the run is labelled `os_readonly_roots` with that root recorded. Inside, the agent appends to `.aew/state/control.yaml` (succeeds; the host file changes), reads and writes the sibling run's `harness/session.db` holding its bridge key, and creates files under `.aew/evidence/`. Only the git metadata stays protected, because its re-binds come last. With control state writable the agent can forge authority outright; with another run's key it can act as that run (the area 2 F2 vector this amendment set out to close).
- **Scenario (E2):** `containment.writable: [/tmp]`. The self-test passes; the host `/tmp` returns over the private tmpfs, and every `aew-bridge-*` socket directory of every other run on the host is listed and writable from inside.
- **Contrast (E3):** a root over `$HOME` or the workspaces root is caught, because the sentinel lives in the workspaces root.
- **Fix:** in `for_run`, refuse (with `ContainmentUnavailable`) any operator root that equals or contains, or lies under: the project root's `.aew`, the git common dir and the worktree gitdir, the runs directory, the bridge directory, `/tmp`, `sys.prefix`, and the secret masks. Separately, widen the self-test so a layout that reaches those places fails closed whatever created it: add `.aew/state/control.yaml` (or `.aew` itself), the runs directory and a marker file in the host `/tmp` to `protected`, and probe `access(W_OK)` on them like the git paths. Do not try to fix it by re-binding `.aew` read-only after the writable binds: a later mount at `.aew` would shadow the runs tmpfs beneath it and make sibling runs visible again.
- **Reproduced:** yes, Rocky 8 (`repro/run-experiments-rocky8.log`, E1 and E2). Confidence: high.

### F2. Minor — `procs.host_pid` returns the queried pid as a host pid when nothing matches, and matches only the innermost namespace pid

- **Where:** `src/aew/harness/procs.py:301-322` (`ids[-1] == ns_pid`; `return matches[0] if matches else ns_pid`).
- **Guarantee:** ADR-0009 M4-B "`procs.host_pid(ns_pid, under=<bwrap pid>)` translates it through `NSpid`, looking only under the run's own bubblewrap processes"; the research §9 row 3, which found the untranslated form watched unrelated host processes.
- **Scenario (E4):** inside a contained run the agent starts a nested sandbox (`bwrap --unshare-pid ... sleep`) and reports the sleep's pid as seen from the run's namespace (6). No process has innermost `NSpid` 6 under the run, so `host_pid(6, under=bwrap)` returns 6, a host pid that is not under the run's bubblewrap at all. `host_pid(4000000, under=bwrap)` likewise returns 4000000. A caller that trusts the result watches, or kills, the wrong process. The nested bubblewrap's own pid (3) translates correctly. The only current caller, `tests/helpers/fake_harness.py:232`, discards a result equal to its input, so the live E13 test is not misled; the function's contract is.
- **Fix:** when `under` is given and nothing matches, raise `LookupError`; match the `NSpid` entry at the run's namespace depth (`len(ids) == 2 and ids[1] == ns_pid` for processes directly in the run's namespace, or the depth of bubblewrap's init under `under`) rather than the innermost entry; and make the helper's `- {recorded}` unnecessary.
- **Reproduced:** yes, Rocky 8 (`repro/run-experiments-rocky8.log`, E4). Confidence: high.

## What looks sound

- **Bind order and escapes.** Host root read-only first; `/dev`, `/proc`, `/tmp` private; the project visible read-only; the runs directory hidden with only this run's directories bound back; writable roots; read-only re-binds (git metadata, a reader's workspace, the bridge directory, the interpreter) after every writable bind; masks last, by type. The §12 escape list is refused by the OS with the host byte-identical (tests, and E0 here).
- **Git metadata and the confused deputy.** `HEAD`, `index`, `commondir`, `gitdir`, the AEW marker, refs, objects and hooks are read-only; the `.git` pointer file is re-bound over the writable source; the agent's `commit`, `checkout --detach`, `branch`, `update-ref`, `stash` and `--git-dir` overrides all fail; the engine commits and fingerprints from content with the real index; the private store is scratch that nothing real refers to and is removed when the run ends (and when a check is killed with it).
- **Sibling runs and the bridge.** Other runs' directories are an empty tmpfs; the bridge socket is created under the host `/tmp` regardless of `TMPDIR` and only the run's own directory is bound in, read-only, which is enough to connect. This closes the area 2 F2 vector under the default policy.
- **Fail closed.** `ProcessTree(require_layout=True)` from construction until the layout passed its self-test; `establish` raises under `required` for every unavailability; the adapter is loaded after; checks run through the same tree and are killed when the run ends, and a check the end cut short records nothing.
- **Process ownership.** PID namespace per run; the recorded pid is bubblewrap's host pid, which leads the process group; `killpg` plus `--die-with-parent` plus the sentinel; `setsid`, double fork, `SIGKILL` of bubblewrap and `SIGKILL` of the owner all end the tree (tests pass here).
- **Labels.** Structured, mechanism-named, `network: not_provided`, integrity-only wording in the ADR, `doctor` builds and self-tests a live sandbox, old records normalize, the server-environment residual is documented and asserted.
- **Role table.** Exhaustive and tested against the archetype list; write access only for an implementer in a Ticket scope.

## Process, architecture and efficiency notes (outside the findings)

1. **The self-test proves a fixed shape, not the layout's negative space.** It is a regression guard for bind-order mistakes in AEW's own layout, and good at that. It is not a check of what the operator added. Saying so in the ADR, next to the fix for F1, keeps the label honest about what the self-test vouches for.
2. **`required` on non-Linux POSIX.** `mode()` returns `allow_weaker` wherever `supported()` is false (`__init__.py:39-44`), and the ADR describes that downgrade for Windows only. On macOS or another POSIX host, `mode: required` launches uncontained with a `workdir_separation_only` label and no refusal. Either refuse there, or say in the ADR that `required` means "required where containment exists".
3. **`_git_metadata` swallows `AEWError`** (`layout.py:156-160`) and returns no protection. For a writing role `private_git` raises anyway, so launch fails; for a reader the workspace is read-only regardless. Harmless today, but a silent empty `protected` list is the kind of thing F1 shows the self-test will not notice.
4. **Masks are computed once, at launch, for paths that exist** (`layout.py:113-126`). A secret created on the host during a long run is readable. Worth a sentence under residual risk.
5. **Operator `writable` roots are also the natural place for a shared build cache**, which is the stated use. A `writable` root under the project (for example `<project>/build`) is fine under the F1 fix; the refusal list should be stated in the policy schema's description so operators do not discover it at launch.
6. **Test cost** is small (35 s for 35 tests on the VM); the containment lane is cheap enough to run on every PR that touches `harness/`.
