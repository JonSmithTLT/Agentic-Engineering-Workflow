# AEW D-01 — Shared Read API and Private Website Wire Contract, Candidate v0.3.2

**Date:** 2026-10-16  
**Status:** PROPOSED IMPLEMENTATION-INTERFACE CONTRACT — **NOT OPERATOR-ADOPTED, IMPLEMENTED, OR SECURITY-QUALIFIED**  
**Authority:** The eleven previously adopted normative sources and D-01 operator-adopted read-first and bounded Knowledge Journal scope. In particular, AOI v0.2.2 and D-02 AEV G1 v0.2.1 govern meanings and qualifications. This document does not amend them.  
**Review target:** This document, `openapi-read-candidate.yaml`, `schemas/aew-d01-read.schema.json`, `tests/semantic_checker.py`, `tests/validate_v032.py`, the typed fixtures and producer/security appendix are **one proposed versioned contract**; a team cannot adopt the schemas while ignoring the checker assertions and listed W4 duties.

## 1. Goal and scope

Backend and private website implementations **shall be substitutable** without bilateral negotiation of missing interface semantics. The committed read profile covers J01–J04 and J08; J05 supports accepted limited research references and the operator-approved **read-only Knowledge Journal**. J06 has no mutating API; J07 supports qualified historical/degraded *online* reads, not a G4-qualified offline reader. G1–G4 remain OPEN. An initial as-built G1 baseline for `main` has **not** been operator accepted. No URL, HTTP success, schema shape, source label, or test result creates protected authority.

The interface currently defines **14 GET operations**, including **one bounded exact-subject resolver**. It makes no protected command submission, approval, grant, publishing, HOLD release, attachment mutation, event subscription, notification service, global snapshot, identity service, or Knowledge admission service mandatory. Source owners may use any compatible internal implementation. Domain conclusions remain under ADC/AEV/HEB/WIS/CNI and other actually adopted competence, not transport, website, or a generic `RELEASE`/`KNOWLEDGE` tag.

## 2. Required wire and security envelope (D01-WR-01–04)

**D01-WR-01 — Transport.** GET-only HTTP/JSON profile, UTF-8, OpenAPI 3.1, Draft 2020-12 schemas and version `0.3.2-candidate`. All controlled 200 and error responses **shall** include `X-AEW-Wire-Version: 0.3.2-candidate` and `Cache-Control: private, no-store`; 200 media type is `application/json`, errors `application/problem+json`. `Accept: application/json` required on reads. Headers are present in the machine-readable specification. The website does not persist protected responses as an offline authority cache.

**D01-WR-02 — Reader credential qualification.** A transport bearer token is *only* a carrier credential. It cannot identify a human independently from an agent able to acquire or replay it. For any operator-only or otherwise more privileged disclosure than an agent holder could legitimately have, a **separately qualified read-principal binding and credential isolation** shall establish the effective principal, accepted lineage/assignment, present entitlement, and revocation. The read-origin qualification is a distinct **W4 read-security prerequisite**, not a declaration that G3 command authorization is qualified and not an additional independent decision authority. It is permissible to qualify it within the same protected ingress mechanisms as G3 when evidenced.

**D01-WR-03 — Shared-login fail-closed read profile.** Where a read credential is reachable by an implementing agent (e.g., shared-login browser profile/CLI token), the protected read ingress **must not** attribute operator-only disclosure to it. Such reads are restricted to the intersection of the disclosure scopes that *every plausible credential holder* could legitimately exercise for the requested subject. If no safe common scope exists, return non-sensitive `404`/`503` or a qualified permitted minimal projection; do **not** return operator-only independent verifier or unrelated lineage material. Two requests using the same replayable bearer alone cannot be reliably distinguished as genuine operator versus agent: both get the same bounded result. This does not block a useful J01/J03/J05 read-first product serving verified shared-scope information, but W5 requires an actual positive composed inspection path, not all unknown/unsupported cards. Server/service credential privileges never widen the original caller's rights.

**D01-WR-04 — W4 qualification.** Real qualification must test read-principal binding, agent process replay, copied browser tokens, privilege confusion through carrier identity, entitlement revocation, cross-lineage subject disclosure, response-form side channels, and caches. An operator token replayed by an agent from the shared-login host must receive no greater disclosure than the authorized agent-equivalent profile. This scenario is a **W4 future test obligation**, not something the offline JSON checker purports to prove. G3 still prevents operator-only command activation.

## 3. Route contract and exact identity (D01-WR-05–07)

**D01-WR-05 — Operation definitions.** The canonical endpoint list and exact 200 type are in `openapi-read-candidate.yaml`. The same 13 original proposed operations remain; one bounded `GET /v1/read/resolve` accepts an exact typed `SubjectRef` through query fields and returns one `subject_detail`. Its allowlist is assurance basis, determination, evidence, HOLD, composition commitment, dependency conflict or package; it is **not** an unrestricted graph/search API. Each GET has an operation-specific `Read...` response schema requiring the correct `resource_type` and `mode`. List `items=[]` means only no *currently disclosed members* of that caller's view. `outcome=provided` or `historical` for a detail request requires exactly one matching item, otherwise absent/undisclosable is an indistinguishable 404; 200 with unknown/incomplete facts is allowed only for a known authorized subject and must retain truthful qualification.

**D01-WR-06 — Canonical subject ID binding.** Canonical subject IDs are exact opaque stable identities, not route-convention substrings. Path parameters named `*_id` use **unpadded canonical base64url of the UTF-8 exact ID bytes**, which the backend strictly decodes once, checks for valid UTF-8 and allowed canonical ID, and verifies by re-encoding to the exact original segment. Slash, percent, Unicode normalization, alternative padding or noncanonical encodings must not change identity. The resolver uses exact `id` in RFC3986 query encoding, decoded **once**, with any extra/duplicate/double-encoded ambiguous input refused 400. `kind`, `revision`, `generation` and `package_digest` remain independent typed identity dimensions. A detail response's exact identity must match all supplied request dimensions, not merely its JSON structure. The request/response identity assertion is mandatory in `semantic_checker.py` and provider/consumer conformance; use `GET /resolve` for IDs not natively addressable in other committed route types.

**D01-WR-07 — Typed link resolution.** Only `Link.availability=navigable` may be emitted; links to undisclosable, unsupported or unknown target subjects MUST NOT be serialized, even as per-hidden-record placeholders. `Link.availability=navigable` is permitted only if an exact authorized target is resolvable under one of the committed operation mappings. Supported `subject_detail` kinds use `/v1/read/resolve` with the **entire** exact target SubjectRef; accepted work and eligible package/Knowledge detail use their declared typed GET routes. The website constructs URL parameters from the canonical target using the specified encoding, never guesses a URL from a label, agent text or source ID prefix. Every follow-up read rechecks current recipient eligibility. No restricted, unknown or unsupported `Link` object is emitted. If owner policy allows a generic unavailable-navigation statement, it is a separately qualified aggregate statement unrelated to hidden member cardinality, never a placeholder for each hidden target. The resolver shall return a uniform 404 Problem for nonexistent AND unauthorized/undisclosed subjects, with the same body, headers and response size class; a 200 undisclosable `subject_detail` is forbidden. W4 must compare real hidden and fabricated IDs under matched context, including network response metadata. IDs of restricted verifier subjects should be unguessable as defense in depth; this is not an authorization substitute. F01/F02/F04 and F13–F16 demonstrate positive navigation of O4, H-1, P-A and an accepted interface, with a private target requiring indistinguishable refusal in W4 tests.

## 4. Typed envelopes, cross-field validation and error handling (D01-WR-08–11)

**D01-WR-08.a — Single-effective-recipient response identity.** Every response shall contain one `effective_recipient_ref` and every returned `Resource.disclosure.effective_recipient_ref` shall be exactly that value. Layer B rejects even one divergent item. Mandatory request binding additionally compares the response-level identity to the server-established effective principal for the specific request, *not* a principal self-declared by the JSON document; actual protected identity binding and entitled disclosure remain W4. Source-owner diversity under one recipient is permitted.

**D01-WR-08.b — Deterministic evidence consistency.** A qualified-clear assurance must carry a qualified AEV governing `data.readiness` field source bound to the AEV source fact and an exact AEV comparable closure-set witness. The applicable roster and HOLD closures must match the corresponding entries actually attested by that source as `domain, owner, epoch, version, coverage_ref, completeness`; *distinct roster and HOLD epochs are legitimate*. Absence or contradiction fails closed. Source assertion authenticity and whether it truly covered accepted revision and materially complete inputs remain W1/W4 evidence, not claims a JSON checker can prove.

**D01-WR-08.c — Bounded JH-P01 Journal selection.** Every `ReadKnowledge` response explicitly distinguishes an AEV-qualified selected Journal universe (`journal_selection.status=qualified_scoped` with source proof, recipient scope and matching qualified `collection_basis`) from an unestablished/unavailable selection producer (`not_established` with no source). A zero-item Knowledge response without the former **cannot** be rendered as a source-qualified empty Journal. `data.eligibility` must be sourced from a competent, AEV-qualified `governing_determination` / `qualified_source_basis`, not an `unqualified_report`. The original `assurance_determination` ID, WIS accepted-revision SubjectRef and affected work identity are recorded in one AEV-issued exact `assessment_binding` tuple and checked for consistency. The tuple's issuance is operational W1 evidence; this deterministic redundancy prevents incompatible interpretation, not spoofing. Cross-revision mismatches fail closed.

**D01-WR-08.d — Impact partitions and partial independence.** `known_affected`, `qualified_unaffected` and `impact_unknown` are pairwise disjoint as complete six-field `SubjectRef` tuples within one assessment; no absence of a recorded edge proves unrelated work. For this `WaitingData` projection, `ImpactAssessment.accepted_revision` is precisely its `data.work.revision` dimension; different accepted-revision *subjects* require their own full canonical WIS references. Each nonempty `qualified_unaffected.refs` must have a qualified CNI `unaffected_subset_basis` (including when overall `qualification=not_established`), attested for the same field source and bounded binding-coverage context. This expresses individually proven unaffected work amid unknown other consumers without falsely completing the assessed universe. For any future `qualified_complete` extension, the union must equal the separately qualified *disclosed* assessed set; no hidden membership or global completeness may be inferred from local lists.



**D01-WR-08.e — Current qualified unaffected-subset source and comparability.** A nonempty `ImpactAssessment.qualified_unaffected.refs` is a consequential **positive present-applicable independence** assertion even if the enclosing assessment is `not_established`. The CNI `data.impact_assessment` field source, embedded `unaffected_subset_basis`, and separately issued `unaffected_scope_comparison.comparison_source` SHALL each be a qualified, present-current, governing CNI SourceStamp, checked with all ordinary source/renewal/observed/as-of/evaluation-time rules. The comparison SHALL identify the exact accepted revision, bounded assessed universe, binding-coverage reference, fact, source epoch, version, and coverage reference on **both** the CNI impact field source and subset proof; their declared identities SHALL match the actual stamps. Its CNI-qualified comparison stamp SHALL itself cover the declared binding-coverage reference and be temporally valid. Matching source stamps alone are not sufficient evidence of assessed binding coverage. Source fact versions and coverage scopes MAY differ where the CNI comparison explicitly attests their applicability under the exact assessed scope; otherwise any missing, expired, historical, contradictory, future-dated, or unqualified input forbids the positive unaffected claim. This is deterministic internal coherence; W1/W4 still independently establish actual CNI source competence and authentic owner qualification. Historical inputs may be displayed separately, but do not confer current continuation. A fully unknown universe with a positively qualified subset is valid (F28/F31); failure of its basis downgrades/quarantines the affected positive independence claim rather than imposing an invented global HOLD on unrelated work. The wire MAY retain `qualification=not_established` for the overall assessment while presenting an independently valid owner-qualified unaffected subset.


**D01-WR-08 — Normative validation layers.** Providers **must not emit** and consumers **must reject/quarantine** inconsistent consequential projections. Layer A runs first. A schema-invalid document is rejected without invoking Layer B; the reference checker is defined only over Layer A-valid documents. This has three distinct layers: **(A)** Draft 2020-12 JSON Schema route/resource/deterministic condition validation; **(B)** the machine-readable *semantic assertions defined in this document and represented by the normative reference-checker `tests/semantic_checker.py`*, including temporal relations, request/identity matching, repeated sources, and mixed-owner consistency; and **(C)** independently evidenced W1–W5 source integrity, actual entitlement, proof authenticity, source continuity, redaction and browser inert rendering. The reference checker is a versioned behavioral oracle, not a requirement to deploy Python or a grant of AEV/Knowledge authority. Equivalent implementations must produce the same accept/reject/downgrade decisions on shared fixtures. If a projection fails A or B, consumers **must not** display it as present-current, clear, accepted or actionable; quarantine the affected card, show a generic integrity/unavailable indication and record diagnostics without leaking hidden records. Do not treat failed validation as a new AEV HOLD or as a successful read. No new read with broader privileges is authorized as an automatic recovery.

**D01-WR-09 — Deterministic schema relations.** `ReadResult` mode and outcome constrain list/page/detail multiplicity. Route variants constrain item types, resource type constrains canonical reference kind and typed `data`, and required `FieldSource` mappings are checked with `contains`. The closure domains for obligation roster/hold set are exactly AEV-owned; accepted-revision membership closure is WIS-owned. Qualified-clear assurance requires AEV source `qualified` and `present_current`, all-satisfied obligations, no qualified outstanding HOLD, qualified complete independent roster and HOLD closures, and a currently authorized `full` or owner-qualified coarse disclosure. `agent_attention` never carries owner-critical priority. A `delivered` or `cited` activity cannot set `benefit=supported`; benefit requires a distinct qualified evaluation and evidence. A list with `has_more=true` requires a non-null next cursor, and `has_more=false` requires null. Extra/unrecognized discriminants fail closed, rather than silently falling back to PASS, READY or eligible.

**D01-WR-10 — Source-of-truth fields.** `field_sources[]` is the **only** per-field source-stamp representation. `PackageData.g1_source` and `.designation_source` from v0.1 have been removed; duplicate field-source paths conflict and are rejected. `data.g1` is attributable to AEV, package identity to WIS and protected designation, when asserted, to HEB. A historical AEV `CONFORMING` determination may be shown as historical if independently qualified and disclosed; it does not confer **current progression**. An unavailable/unqualified G1 producer cannot supply qualified conformance simply because the API currently responds. F09 and F17 exhibit the difference. Qualified Knowledge observation receipts do not become Knowledge admission.

**D01-WR-11 — Errors/status.** Allowed Problem statuses/codes are exactly: `400/invalid_request/never`, `401/authentication_unqualified/reauthenticate`, `404/not_found_or_not_disclosable/never`, `409/cursor_stale_or_unauthorized/refresh_read`, `503/owner_unavailable/when_source_recovers`. The emitted HTTP status MUST equal `Problem.status`. Detail nonexistence, insufficient entitlement and revoked detail rights are indistinguishable `404`; list/cursor continuation after scope change gives `409` with no private source hint. A normal owner-incomplete but readable record can be an explicitly limited 200; missing safe projection is 503, not a fabricated 200 clear. 403/422 and unused old Problem discriminants are removed. Unknown wire version fails closed at transport compatibility boundary, without making the backend reveal restricted subject existence. Do not echo protected IDs in Problem diagnostics. Both successful and controlled application-error responses require the declared headers. A protocol-level denial, server fault or intermediary response (for example 405 for an unsupported method, 413 for oversized payload, or 500 for provider failure) cannot be represented as 200 success or authorization; consumers MUST fail closed as transport/integrity unavailable. These are **not** promises that a 200/Problem response exists, nor a second subject-level denial vocabulary. Any transport refusal that is governed by the protected AEW ingress must avoid hidden subject-existence leaks. This GET profile does not specify HEAD or conditional 304 as contractual read results; an implementation may use them only as independently qualified optimizations that preserve recipient/owner currentness and never bypass a full authorized observation.

## 5. Source provenance, currentness and disclosure (D01-WR-12–16)

**D01-WR-12 — Qualification is per source fact.** `SourceStamp.owner` identifies a source/issuer *namespace*. Its new `authority_class`, `governing_owner`, `issuer_ref` and `owner_coverage_class` distinguish authenticated service receipt, protected source observation, and a competent domain decision. The namespace `KNOWLEDGE` can issue an engine-authenticated Case or delivery observation, but does not admit a Lesson, authorize serving or certify benefit. `RELEASE` can project documented journey coverage and observed test receipts; it cannot adopt release commitments or certify W4 without underlying competent operator decision and actual evidence. The accepted operator release decision is distinct from a runtime conformance producer. For consequential derived fields include an exact qualified governing source in `field_sources[]`; if the required governing authority is absent, report `not_established`, not an invented owner. A SourceStamp string reading `qualified` is a **claim requiring W1/W4 verification**, not itself source proof.

**D01-WR-13 — Source-backed renewal.** A present-current item must have qualified governing source support and a separately qualified renewal condition. `Renewal` binds a proof reference to competent `qualified_owner`, exact `source_epoch`, `coverage_ref`, `checked_at`, finite `valid_until`, method and invalidation condition. Both supported modes, `source_valid_until` and `qualified_continuity`, have a **finite source-qualified observation bound** in this candidate; a future continuously verified form without a finite bound would need its own exact independently implementable verification semantics and adoption. `qualified_continuity` here means source-qualified revalidation/continuity *up to its finite bound*, **not indefinite green on quiet transport**. Source-level renewal may be refreshed by a new authenticated comparable owner proof, never by API HTTP receipt timestamps or a polling-local clock. If source vanishes, a proof invalidates, epochs cease comparing, or no source-backed renewal occurs by the governing boundary, downgrade to historical/revalidate-required/unknown. No universal TTL is chosen; each actual bound is declared by its source. The source proof must be checked by protected provider security, not forged by request fields.

**D01-WR-14 — Clock and mixed-page rule.** For a source-issued `valid_until`, the provider and website must conservatively cease presenting present-current no later than expiry. Compare RFC3339 instants in UTC; if client clock has documented uncertainty, **downgrade when local time plus maximum possible ahead-of-real error reaches `valid_until`**, never use skew to extend beyond source validity. Where accurate time/uncertainty cannot be established, refuse a present-current representation and retain qualified historical-as-of information only. `observed_at` and `checked_at` may not fall after a renewal's `valid_until`. In this wire profile, a currentness proof checked **after** the declared `projection_as_of` cannot retroactively qualify that as-of state; providers must issue a new qualified projection boundary or a separately specified owner-proof profile. `ReadResult.collection_basis` qualifies the owner-issued collection observation for the exact recipient view, epoch and bounded set when supplied; it never upgrades any item. The selected Journal history has an AEV-qualified eligible-determination collection source and exact selection/coverage predicate, including when the qualified eligible set is empty. A missing producer cannot be represented as a qualified empty set. `ReadResult.continuity=source_qualified` cannot upgrade any inner item's historical or unknown state, nor field-level AEV/HEB/Knowledge qualification. It is a page-level provenance/continuity claim, not a blanket clearance. Where source/closure epochs disagree, an owner must recompute; client cannot synthesize missing equality.

**D01-WR-15 — Source-set closure vs visible members.** `Closure` qualifies the owner's complete accepted revision membership, AEV mandatory roster, or AEV applicable HOLD set **in its declared source scope/epoch**; it is NOT the recipient's visible-member list. `MemberView{visibility,refs}` is distinct: `complete_visible` means all members within exactly that permitted field/subject scope are shown; `partial_visible` means only a disclosed subset; `members_withheld` or `unknown` has `refs=[]`, whose emptiness makes no global-absence statement. A `qualified_coarse` resource may preserve a separately qualified, recipient-authorized AEV conclusion and owner-set closures while carrying **withheld member arrays**. This does not leak withheld member counts or IDs and is not downgraded solely because the underlying private details are withheld. Conversely, a visible empty list is never evidence of no canonical HOLD, no mandatory obligation, no child or no Knowledge activity. The same distinction applies to scoped work children/accepted interfaces, Knowledge origin roots, waiting basis and recipient-view pagination. Non-disclosable conclusions must not appear as a coarse qualified outcome. F12 is the positive restricted-member scenario; no release policy is inferred by browser code.

**D01-WR-16 — Effective recipient noninterference.** The disclosure decision binds exact effective principal, root/accepted lineage, assignment, subject, purpose, confidentiality and current revocation state, not a role/class alone; the most restrictive contributing owner limits release, with any owner-qualified aggregate conclusion separately released under a prequalified policy for **that recipient context**. Hidden verifier drafts must not affect implementer-visible conclusions. Cursors, request denial distinction, array sizes, counts, timing categories, result order and link existence must not leak hidden activity. Tests compare two worlds with matched public inputs, observation context and normalized independent request volatility; no unauthorized hidden-dependent changes. All narrative, ANSI/terminal controls, HTML and URLs are inert in browser, CLI, digests and any committed secondary read surface.

## 6. Pagination and navigation continuity (D01-WR-17–18)

**D01-WR-17 — View/cursor.** Layer B must verify page-size bounds, strict ascending sequence, and no duplicate full tuple within a page. Null fields order before any non-null string and non-null values compare using exact UTF-8 byte order, not locale normalization. List pages are sorted by **canonical Resource `resource_type`, `ref.kind`, `ref.id`, `revision`, `generation`, `package_digest`** as ASCII UTF-8 lexicographic tuples, with null sort before non-null and each identity emitted at most once per qualified list view. Cursor position is bound to this tuple and to recipient identity/context, query filters, qualified disclosure scope, governing comparable collection epoch(s), page-size and view membership/order version. Cursor data must be tamper-evident (e.g. protected MAC with current key or equivalent server-held opaque state); it is not a grant. On scope revocation, comparable-set membership change or failed continuation qualification, return a single safe `409` and require a fresh read; do not silently combine pages into misleading complete-set claims. No global synchronous snapshot/broker is required. Providers may use stable per-owner view generations or independently qualified equivalent ordering to meet this guarantee.

**D01-WR-18 — Count and visibility.** Do not expose total global count, global sequence number, filtered member gaps, global pagination offsets, or cursor length correlated with forbidden records. `PageInfo.membership` describes only the currently authorized recipient view. `has_more` means only a next page in that view, not that a hidden record exists. Revocation of prior cursor authorization cannot be bypassed by replay. When source visibility cannot be safely qualified, an explicit scoped/unknown view or a uniform unavailable/error response is required, not guessed full coverage.

## 9. LCO v0.2.1 adopted nonnormative design baseline — derived interface duties (D01-WR-23–30)
