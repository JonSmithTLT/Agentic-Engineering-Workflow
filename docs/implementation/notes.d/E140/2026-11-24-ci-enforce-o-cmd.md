**O-CMD's triage, ahead of its flip.** The flip itself is not in this change: it waits for a full-tier run with these fixes (below). O-CMD's keys new against the allow-list were read from `main`'s own runs: nine full-tier push runs in a row, from `68d19082` to `61f22f3e` (run 45331260009 to run 45376838947), each with `assurance` green, reported the same 18 new and 10 stale O-CMD keys. Each new key was traced to the text that fires, by running the tests that reach it with the capture on (Linux, local) and reading the finding's detail. Every one comes from one of three causes:
- **The rule's false positive (5 keys, `tool:message_send|*`).** The rule checked a typed tool's name against the catalog with every switch off (`contract.TOOLS`), so `message_send`, behind the messaging switch, was flagged in its own results. It now checks against the catalog with every switch on (`rules.known_tools`, from `contract.catalog`). O-SECRET's argument audit reads that catalog too: `message_send` has no credential-named argument, so it adds no finding.
- **Steering commands named bare in a wait's next step (2 keys, `cli:aew harness wait|result` and `tool:harness_wait|result`).** The wake guide's `aew harness send` and `aew harness interrupt` are mentions in the Lead's system text, but a returned `next_action` is offered to be run as given. A step now writes them with the run and the message (`contract.steer_commands`); the system text is unchanged.
- **Commands named bare in a Ticket's next actions (11 keys, on `integration_publish`, `resolve`, `ticket_prepare`, `ticket_request_review`, `ticket_request_verification` and `ticket_start`).** These are the hints `status` and `resume` give, and the stage tools carry them in their results and refusals: `aew integrate publish`, `aew review ingest`, `aew verify ingest`, `aew integrate prepare`, `reconcile`, `requeue` and `validate`, and `aew invoke create`. Each is now written whole, with its Ticket, its evidence where one is named, and `--expect-rev`.

The note of 2026-11-06 names two keys. `cli:aew harness status|result` has not been an O-CMD key in any of the nine runs (it is still an O-IDS key). `tool:integration_publish|result` is the bare publish above, and is fixed here. The 10 stale keys are removed from the allow-list here with `--remove`. Fixing these sources also stops some allow-listed O-CMD keys from firing: in the files run locally, none of the 3,270 judged outputs had an O-CMD finding after the fixes, where `status`, `resume`, `explain`, `resolve` and `work dispose` results had them before. In shadow a key no longer observed is only reported. This change's own full-tier run lists exactly which keys are now stale. The flip removes those keys and turns O-CMD to `enforce`.
