**Built, the CLI half (`feat/e170-record-body-read`): `aew record body <id>` prints a record's body as written.** It answers for a work unit's record (the Ticket's, Story's or Epic's description) and for an evidence record (a report, a review, a research or discovery record, a plan proposal or assessment), current or archived: `aew history show` answers only for finished work and gives the body as an escaped string inside JSON. The engine's read is `HistoryCommands.record_body`, which reads through the accessors `work show` and `history show` use and checks what it returns the same way: a current evidence record against its seal and, once ingested, the hash its unit pins (`knowledge.evidence.find`, which lists a unit's evidence and never builds a path from the id); an archived one against its bundle (`held_evidence`); a unit's record against the hash control state pins. **As written, and safe to print:** line breaks, tabs and quotes are printed as they are. The body is an agent's or a person's text, so a character that could steer a terminal (an escape or OSC sequence, a carriage return, a C1 control, a bidi override) is printed visibly as `\uXXXX`, by `coordination.render.escaped`, the rule a worker's message is already shown under. `--json` gives the exact text with the record's kind, unit, whether it is archived and, for evidence, whether the engine or a model wrote it; there is no other exact-bytes option, since no command has one. **Refusals:** `NOT_FOUND` with reason `unknown_record` (it says where ids come from) or `no_body` (an invocation, a credential, a history record of another kind, a unit created without a body, a check result; it names the read that has the fields), and `INTEGRITY_ERROR` for a record that is not what was recorded (reason `not_text` when it is not UTF-8). **Who may read:** it takes no credential and no expected revision, and it grants nothing. It reads the project's own records under `.aew`: what `work show` and `history show` read, and a current unit's evidence, which lies beside them and which every reader of the project already sees. So it widens no reader: the Lead's session runs it locally (`lead_broker.CONTAINED_LOCAL`), and what a contained worker can read is decided by its sandbox, as for those reads; the command adds no check of its own and no way round one. **Why this name:** the designer's decision of 2026-10-06 gives `aew evidence show <id>` to the structured, bounded Evidence read, so this command leaves that name free. Tests: `tests/integration/test_record_body.py`, through the real CLI, and the surface map's probe, whose sample Ticket now has a body.

**What remains** on this row: the site's half, which shows the same body, the web developer's (`web/` is untouched here). **Follow-on outside this row's build, as the hold match's note says:** `aew evidence show <id>` with its structured output, bounded bodies and typed Lead tool. No typed tool is added here, so the Lead's tool count and its always-sent text are unchanged; `record body` prints a whole body, with no bound. **Found while building, not fixed here:** an evidence record whose body holds a lone carriage return is accepted at `submit` and then fails its own seal whenever it is read (`INTEGRITY_ERROR`, "was modified after it was recorded"), since `knowledge.evidence.read` reads the file with universal newlines; a carriage return and line feed pair is unaffected. It needs its own row.
