**Built (`feat/scheduler-priority`), the scheduler chain's second PR (E228).** A Ticket's priority is `critical`, `normal` (the default) or `low`, with a reason, set at the draft only: `ticket_draft`'s `priority` and `priority_reason`, or `aew work create --priority --priority-reason`. The operator, 2026-11-10: it is "not a field that would cause us to have to throw a ticket away if its wrong", so it is fixed for now; changing it later is a row of its own.
- **The levels' owner** is the control schema (`work_unit.priority.level`). `aew.engine.priority` and the Lead's tool both derive them from it, so the MCP process serves the list without the engine.
- **A `critical` or `low` priority needs a reason.** A priority on a Story or Epic is refused. Setting one is a draft, so it stays the Lead's judgment and is never auto-run.
- **The loop's `select`** takes Tickets by level, then by how many live units each unblocks (its effective dependency edges, own and inherited, derived each tick), then by id. A `low` Ticket starts only when no `critical` or `normal` one is eligible. Nothing is pre-empted. With none eligible, the stop reported is the first in that order. Starting a Ticket stays `ticket_start`, CAS-checked as before, so the loop and the Lead can't double-start one: E227 needed no new tool name (E231).
- **`status`** shows a priority that isn't the default beside its Ticket, with its reason and a `low` Ticket's age. The generated `CURRENT.md` shows the level and reason but no age, so it stays a function of the state. The status report's `work` entry carries `priority` only when it isn't the default.
- **The Ticket field registry's first version step, v2:** a non-material `scheduling` group holds `control:priority`. Every other group's digest is unchanged, and a priority never stales a Ticket's evidence.
- **Not done here:** the dashboard's work item doesn't show the priority yet (E227 names `status`); changing a priority after the draft; E229's priority floor; E299/RS-41.
