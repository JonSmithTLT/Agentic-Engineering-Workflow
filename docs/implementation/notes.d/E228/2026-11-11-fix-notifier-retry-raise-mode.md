**Built (`fix/notifier-retry-raise-mode`), the notifier's two small fixes of the designer's ruling of 2026-11-11 on SYS-04's held items, part 4 (a row is owed; noted here until it is filed):**
- **(a) Retry once configured:** a delivery that failed because of the notifier itself (`not_configured`, `unavailable` or `not_executable`: `notify.NOTIFIER_FAILURES`) leaves its key open in the delivery log, and the watcher offers it again on the first pass where `notifier_problem` is clear. While the notifier still cannot deliver, an open key is not offered, so no failed line is added each pass. Every other outcome stays once per key, and a delivered key is never sent again: the log is read oldest line first, so a key's latest line decides, across restarts too. A key leaves the outstanding set only after the log records it, so passes racing the delivery thread never send it twice. Tests: `test_a_request_recorded_before_the_notifier_is_delivered_once_it_is`, `test_a_request_recorded_while_the_default_desktop_notifier_was_unavailable_is_delivered_once_it_is`, `test_a_delivery_that_failed_for_another_reason_is_never_offered_again`, `test_passes_racing_the_delivery_of_a_reopened_request_send_it_once`, `test_a_key_s_latest_line_decides_whether_it_is_open`.
- **The limit:** only an event a pass derives again is offered again: the open conditions (the Lead's requests, the validation breaker, a high anomaly, a reconcile mark) and liveness. A transition (`generation_ended` by takeover, handoff or release) and a spool line are read once past their cursors, so one that failed because of the notifier is not re-sent. Covering them needs the outstanding set to hold failed events, a design the ruling did not ask for.
- **(b) The raise toast names the mode:** a `raise_requested` toast's title names the mode asked for (`AEW: raise requested to run`), taken from the event's `ref` only when it is one of `steering.MODES`; any other event's `ref`, and a raise's that is not a mode, is never shown. The toast still never carries the event's `reason`, the Lead's rationale. Tests: `test_a_raise_toast_names_the_mode_asked_for_and_never_the_rationale`, `test_a_toast_names_no_ref_that_is_not_a_raise_s_mode`.
