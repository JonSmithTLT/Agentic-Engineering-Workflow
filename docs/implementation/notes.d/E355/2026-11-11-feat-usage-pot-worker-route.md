PR #468 adds the worker usage-pot selector and the Linux relay route for a stored plan login.
The execution policy sets the provider default and profiles can override it. API key remains the
default. The plan route stays closed to adoption until the pinned OpenCode version is qualified.
The qualification tool exercises the route with synthetic credentials and a loopback upstream.

The run record and doctor name the pot. Plan runs keep token counts without list-price estimates.
After a plan-login failure, the Lead can relaunch the affected invocation after renewal or cancel it
to clear the steering stop. An unrelated policy adoption preserves an unchanged execution policy pin
when the OpenCode version changes.
