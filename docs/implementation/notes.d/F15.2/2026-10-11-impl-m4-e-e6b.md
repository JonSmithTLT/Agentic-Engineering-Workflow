**E6b, PUBLISH_IF_CLEAN** (2026-10-11; [ADR-0004](../../adr/0004-controlled-integration.md), amendment 2026-10-11;
plan v3 §2.2, §2.3). `ticket_prepare` gains `publish_if_clean`, the Lead's request: the prepare records it on the
lease's queue attempt (`pic_request`, `pic/v1`) in its own commit, so it survives the one rebuild under that lease. In
checks mode the custodian's clean validation commit routes it: the operator's envelope must be usable (else
VALIDATE_ONLY, as with no request), then §17's eight clauses are evaluated in order (`engine/publication_ops.py`). A
failed clause is recorded and the entry goes to AWAITING_DISPOSITION (`pic_not_exercised`); a moved head takes the one
rebuild, and a second move goes to disposition. When all hold, the same commit moves the integration to `publishing`
and reserves one publication, and the custody worker finishes it (`_finish_publish` now takes a principal, the Lead's
or the custodian's), re-checking the request, the envelope and §17 in that transaction before its CAS.
`Kernel.custody_txn` refuses a custody commit that begins or finishes a publication without that check, and the custody
family gains the finish (`integrate.publish`). The count is crash-safe: published in the commit that records
`integrated` (the finish, or `integrate reconcile` after a CAS that landed), released otherwise; a reconcile never
completes a PIC publish whose CAS did not land (the candidate returns VALIDATED). Verifier mode records a request and
never exercises it. Each integration publishing under PIC carries a `pic` record: the envelope, the request, each
clause's result, H, M and the task hash. Invariants 62 to 64.

The normal advertised surface is 11,793 bytes, 15 tools (`publish_if_clean` as plan v3 §2.6 measured it). No new
primitive: the PIC publish is the custodian's, never a stage step, so no declaration changes and SAE-07's custody-sweep
residual (F15.5's note of M4-E E7b) is unchanged. The Ticket field registry classifies the new unit key
`authorization_envelope` as bookkeeping.

Tests: `tests/integration/test_integration_pic.py` (`test_a_clean_validation_publishes_under_the_envelope`,
`test_pic_clause[1..8]`, `test_pic_survives_one_rebuild_only`,
`test_publication_count_survives_a_crash_between_cas_and_count[landed,not_landed]`),
`tests/integration/test_integration_stages.py::test_stage_matches_primitives[ticket_prepare-checks_pic]`, and the
false-advance corpus's `unusable_envelope` case. **Deviations from plan v3, recorded:** clause 4 (the checks pass) is
true wherever §17 is evaluated, because a failing or inconclusive check already takes M4-D5's own path
(VERIFICATION_FAILED, or AWAITING_DISPOSITION) before any PIC routing. `--for` and `--max` are optional: they default to
the sealed manifest's bounds, which ADR-0018 D4 names as the ones the grant gives. A reconcile of a PIC publish whose
CAS never landed returns the candidate to VALIDATED instead of completing the CAS, so that only a current, explicit
decision publishes it (HSD-22, HSD-23). Next: M4-E E7d's events, then E9.
