**A defect fix inside the freeze (2026-11-25, the hand-dispatched nightly's Windows reference serial shard 3/13):** the attempt ledger named a cell's latest attempt by the largest `at` stamp, so two registrations inside one wall-clock tick (15.6 ms on Windows before CPython 3.13) or across a clock step named an earlier attempt the latest, refused a retry of the real one and accepted a retry of the earlier one, forking the retry chain that every later read refuses. The latest attempt is now the cell's last registration in ledger order. No preregistration, frozen record, hash, schema or experiment changes; proved in `tests/unit/test_eval_instrument.py` with the clock held on one tick and stepped back.
