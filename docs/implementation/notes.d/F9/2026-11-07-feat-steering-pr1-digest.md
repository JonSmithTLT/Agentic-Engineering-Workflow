**Steering PR 1, the run's progress digest** (how the Lead waits and is woken; built with messaging still off). The run's meter (`harness/usage_live.py`) now also writes `progress.json` (`aew/run-progress/v1`, `harness/progress.py`) from the same poll: files touched (`write` and `edit` tool parts, at most 50 plus a count), the last command (200 characters, its exit code), the last test (pass or fail, at most 5 failing pytest node ids, else `unknown`), steps, elapsed time, tokens, state, what changed since the last trigger, and the triggers of the closed `why` enum detected there: `run_ended`, `test_failed` (a regression, or the same failure on three runs in a row; a first red run wakes no one), `out_of_scope` and `worker_idle` (after 30 s), at most one per `why` per 30 s, the rest counted. Only a new trigger bumps the wake file. `worker_message` waits for MS4 and `quiet` (`lead.quiet_wake_s`, default 1200 s, 600 to 3600) for the push wake. The harness capability declarations (`harness/harness_capabilities.py`) are built in the same pull request. Still to come in it once E122 merges: the wake guide's rows for each `why`, `harness_wait` returning on a trigger with the wake's shape, the Ticket's scope paths in the launch contract (until then `out_of_scope` reads `unknown` on a real run), and the drift acceptance test's first two steps.
