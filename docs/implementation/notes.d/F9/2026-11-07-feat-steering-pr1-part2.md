**Steering PR 1, part 2: the Lead's wait returns on a trigger.** The wake guide (`harness/contract.py`, `WAKE_GUIDE`) is the one owner of each `why`'s meaning, act and operator line; the progress digest takes its enum from it, and the Lead's text renders the rows a wait can return. The Lead's typed tool `harness_wait` now also returns while a run works, when its digest holds a trigger no wait has returned yet and whose condition still holds (`out_of_scope`: the path is still outside; `test_failed`: the last test still fails; `worker_idle`: still idle), with the wake's shape: `why`, `progress` (each named run's digest), `messages` (none while messaging is off), `next`, and a `next_action` that says what to do and to wait again. Each run's returned mark (`progress.returned.json`, a high-water mark) makes a trigger news once; steering PR 2's broker inherits it. A stated limit: a trigger passed over as stale is never returned once a later one is, and `out_of_scope` fires once per path, so a path reverted and then written outside again wakes no one (the digest's current `out_of_scope` still names it); steering PR 2 settles this with the broker's own mark. The CLI's `aew harness wait` returns only on an end, as before. The launch contract carries the Ticket's scope paths and the workspace's base, so on a real run `out_of_scope` is current: the digest reads the workspace's changed paths (`changed_now`, which sees shell writes and reverts) in the meter's read phase, and its `counts` are absolute. A building run (red after green, no regression) keeps the green pass count as a high-water mark. The drift acceptance test's steps 1 and 2 run against the fake server (`test_the_lead_catches_a_drift_and_steers_it`); steps 3 to 6 need the push wake, steering PR 2, which is next.

**The review round (#358).** `out_of_scope` now reads the scope as its gate does (`policy.guardrails.outside_ticket_scope`, one predicate for both): an empty scope is unbounded, a path outside the workspace (the run's scratch directory) is never out of scope, and only a completed write or edit counts. A `test_failed` trigger holds only while its own test command's latest run is red (`red_commands`; the same command, not the same failing set). A run that stopped early (`-x`, `--maxfail`, pytest's "stopping after") is judged by names, not by its pass count. The digest carries `last_message`, the worker's last words as data (cut to 500 characters, labelled as not instructions), which the `worker_idle` row points at. The CLI's `aew harness wait` is the same wait as the typed tool (the contained Lead's shell relays it). The control lane is checked before the triggers, so an ended invocation's run is never returned as one to steer. For steering PR 2: the still-holds rule, the pending triggers and the wake's shape are `progress.holds`, `progress.pending` and `progress.wake`, and the shape's digests are under `runs` (a timeout's statuses moved to `statuses`). `since_last_wake` stays the meter's for now; its `from` holds the mark in `counts`' keys, so steering PR 2's broker computes it from the absolute counts with its own mark.
