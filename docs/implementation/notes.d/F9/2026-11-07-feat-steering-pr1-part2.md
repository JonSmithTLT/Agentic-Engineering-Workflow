**Steering PR 1, part 2: the Lead's wait returns on a trigger.** The wake guide (`harness/contract.py`, `WAKE_GUIDE`) is the one owner of each `why`'s meaning, act and operator line; the progress digest takes its enum from it, and the Lead's text renders the rows a wait can return. The Lead's typed tool `harness_wait` now also returns while a run works, when its digest holds a trigger no wait has returned yet and whose condition still holds (`out_of_scope`: the path is still outside; `test_failed`: the last test still fails; `worker_idle`: still idle), with the wake's shape: `why`, `progress` (each named run's digest), `messages` (none while messaging is off), `next`, and a `next_action` that says what to do and to wait again. Each run's returned mark (`progress.returned.json`, a high-water mark) makes a trigger news once; steering PR 2's broker inherits it. The CLI's `aew harness wait` returns only on an end, as before. The launch contract carries the Ticket's scope paths and the workspace's base, so on a real run `out_of_scope` is current: the digest reads the workspace's changed paths (`changed_now`, which sees shell writes and reverts) in the meter's read phase, and its `counts` are absolute. A building run (red after green, no regression) keeps the green pass count as a high-water mark.
