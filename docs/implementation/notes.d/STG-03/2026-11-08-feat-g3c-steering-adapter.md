**G3-C's PR C3: the first real protected action.** Where G3 counts, a consumed approval stands in for the typed-back code for one steering raise, at the operator endpoint (`harness/g3_adapter.py`). The endpoint runs the flow itself: it builds the set, asks for the approval, waits, and consumes through `g3client.consume`. The operator still starts it, with `aew lead mode raise`, and a Lead never submits to G3. The typed code is chosen only at the start of a challenge, when the standing fails or the operation has no binding. Once on the G3 path it never moves to the code: no answer, a 503, a 403 or a 400 is held (`G3-11`), and a decline, an expiry or any other consume result is refused. The action is `SET_STEERING_MODE`, carried from `docs/contracts/A-43/` in an overlay (`stg02/g3_overlay.py`) that G3's service and client read and the carrier does not, so no sealed file or pin changes. The one difference from A-43 is the owner label, `ADC`, because the pinned G3 wire has no `R01`; a G3 wire revision adding it is O-01 convergence's. The mode's record names the consent set. Hosts installed before this need the install run again with a wheel that has the overlay; until then a raise is held, and the hold names the install command. A requester that has gone ends the wait, and nothing consumes its approval. The endpoint's console shows how each request ended. `g3/README.md` holds what a host's first raise must show, with the script for a replay.
