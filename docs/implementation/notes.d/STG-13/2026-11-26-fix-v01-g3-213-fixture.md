**The #213 hang diagnosis passes on Linux again (2026-11-26, branch `fix/v01-g3-213-fixture`).** This is the
test-fixture fix that the note of 2026-10-30 tracked. It is cluster C15 of the V-01 re-measure of 2026-11-26.
- **The cause.** The contained Lead's TUI writes its childdiag files to the test's children directory, which
  `autopsy.mark_helper_dir` names in the scripts directory. That directory was not among the offline world's writable
  roots. The sandbox's `/tmp` is private, so the TUI made the directory inside it and wrote there without an error.
  The files were gone when the sandbox ended, and the autopsy kept no `events-*`.
- **Not a product defect.** The autopsy's children directory belongs to the test session, and no installed `aew` knows
  about it. The product's own TUI diagnostics go to the Lead's XDG directories, under the run's harness directory and
  the project's `local/harness/lead`. The Lead's layout already makes both writable.
- **The fix.** The world's `containment.writable` fixture also holds the test's children directory when an autopsy
  session is running (`vertical.scripted_operator.world_fixtures`). The real path checks and pins it, as it does every
  fixture. `test_the_contained_tuis_childdiag_directory_is_a_writable_root_the_real_path_accepts` proves it. The G3-213
  vertical case now passes on its unchanged assertions.

other clusters.
