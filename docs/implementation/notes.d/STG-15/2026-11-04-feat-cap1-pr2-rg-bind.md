**CAP-1, PR 2 of 3 (2026-11-04): ripgrep reaches every contained context, through a mechanism per record.**
- **Built:** `src/aew/capability/bind.py`: every contained context has its own read-only directory first on `PATH`, set by `bwrap_argv`, holding AEW's pinned copy, a host copy named as unpinned, or a failing stub that prints the cause, so OpenCode's lookup never misses and its download is never reached (the designer's CAP-1 ruling 1). `path: own_name` records go last on `PATH`, with no stub. The register is bound read-only. The health check runs inside the sandbox's self-test, and replaces RG-1's doctor line. The fetch runs at the first launch, bounded, and never stops a run. ADR-0009's amendment of 2026-11-04 has the design.
- **Gate rows shown:** CAPR-Q02, Q06, Q08 and Q10, with Q01, Q04 and Q05 on the contained check. Q08's rows against a real OpenCode are `tests/live/test_capability_q08_live.py`, with a control that shows the download's request when the entry is gone.
- **OpenCode's lookup order, read in its source (2.0.18, `cd9a14a6`, `core/src/ripgrep/binary.ts`):** `which("rg", PATH + <bin>)`, then `<bin>/rg`, then the download, with `<bin>` = `$XDG_CACHE_HOME/opencode/bin`. A Lead's server has `XDG_CACHE_HOME` = `<state>/xdg-cache` (`lead._inside`, read, not run).
- **Confirmed by a real 2.0.18 server on the Linux build:** an entry first on `PATH` serves, and a failing one fails the search and downloads nothing; with the entry gone, it sends `CONNECT github.com:443`. A worker's server has `XDG_CACHE_HOME` = `<run>/harness/xdg-cache` (`adapter.server_env`), not the layout's `<scratch>/.cache`. Only `which`'s first hit and the download were exercised, so `<bin>/rg`'s place in the order stands on the source. 2.0.18 only: the ruling's 2.1.4 confirmation falls to H-1, where a version change makes the status STALE and Q08's rows run again.
- **Not reached:** Windows, and a Linux run the policy allows to be weaker, have no sandbox, so no bind, and the download stays reachable there. Those runs' labels say so, and on Windows the capabilities' limitations do. No shipped record uses `path: own_name` yet.
