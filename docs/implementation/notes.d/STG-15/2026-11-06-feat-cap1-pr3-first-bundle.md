**CAP-1, PR 3 of 3 (2026-11-06): the rest of the first bundle, fd, jq, yq, ast-grep and Universal Ctags, as records.**
- **Built:** five shipped records in `src/aew/capability/records.py`, each with a payload for Linux x86_64 and Windows x86_64, a version check, a fixture query and the status `aew doctor` and `aew capability list` read. Each is optional (the harness runs none of them), placed in the sandbox and bound into contained runs like ripgrep, last on a contained context's `PATH` under its own name (`path: own_name`), so a project's own tools keep theirs.
- **Not yet built: agents are not told of them by name.** Only a missing tool appears in an agent's system text, and `yq-go` and `uctags` are names an agent cannot guess. The role cards' capability resolution, the next slot-1 PR, tells agents what they have. The commands are `fd`, `jq`, `yq-go`, `ast-grep` (never `sg`, which is shadow-utils' on Rocky 8) and `uctags`; Universal Ctags' version check names the variant, so Rocky 8's Exuberant `ctags` never passes as it.
- **The fetch takes one new kind:** a payload whose source is neither a `.tar.gz` nor a `.zip` is a bare executable (jq's release form), which names no member and whose download's pin is the executable's. A Python wheel (`.whl`) is read as the zip it is. `payload.kind` is the one owner of what a source downloads, and endings compare without case. `records.record_problems` refuses a member that does not fit its kind, and refuses an archive AEW does not read (`.tar.xz`, `.tgz`, `.7z` and the like) rather than taking it for a bare executable.
- **After the review of #349:** the sandbox's self-test checks the needed tools first, so the five never spend ripgrep's share of its one time budget. In `aew doctor`, an optional tool the operator never chose or declined shares one `UNAVAILABLE` line naming each tool and `aew capability fetch NAME`, in place of a WARN apiece. On a host with no contained context, the consent screen still offers the five, which only `aew capability check` would use there: left as it is.
- **Rocky 8 (glibc 2.28), read from each executable:** fd, jq, yq and Universal Ctags are static. ast-grep's release build needs glibc 2.34, so its Linux payload is the project's own manylinux_2_28 wheel. Linux aarch64 has no payload for these five yet, so it reads `UNSUPPORTED`.
- **Each record's health check was run on its pinned executable,** with the operator's permission (2026-11-06): on Windows 11 through `status.health`, as AEW's copy and as a host copy, and on Rocky Linux 8.10 (glibc 2.28) with the same arguments, fixtures and expected output. All five passed on both.
- **Universal Ctags** publishes no release build for Linux: both payloads are the project's builds of commit 8249436 (ctags-nightly-build and ctags-win32), and that commit is the source (`GPL-2.0-only`). Carrying that source beside the binaries is the offline bundle's (E99), whose design is owed: nothing carries it yet.
- **How the operator gets them:** under the operator's consent rule of 2026-11-05, they are offered on the same screen as ripgrep, as optional enhancements: `all` or `pick` downloads them, as does `aew capability fetch` by name. AEW runs with any of them missing, each reading `UNAVAILABLE` with its fix.
