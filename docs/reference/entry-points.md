# Entry points

Every AEW process entry point, from `aew.process_kind.ENTRY_POINTS`: its kind, where it declares itself, and the places the product starts it. Generated by `python tools/reference.py render`; do not edit. A **store writer** takes the engine's control lock; a **non-writer** reads lock-free only and is refused a lock-taking operation before the lock opens. The set of entry points is complete-by-construction: the table is the registry, and the tests named in `index.json` stop code bypassing it. Each list of a record (`declared_at`, `starts`) is lower-bound, and its `fact_coverage` says what it could not resolve (also in [gaps.md](gaps.md)). A start has a form: `-m` (a `python -m` spawn), `console-script-argv` (an argv constant that starts with `aew`; whether it is run is not decided here) or `console-script-on-PATH` (makes the CLI startable and starts none, so it is listed for every role of the CLI).

### `aew`

- **Kind:** store_writer
- **Why:** the CLI the operator, the Lead and AEW's own workers (the custody worker) run: engine commands take the control lock
- **Declares itself at:** `aew.cli.main:_main`
- **Starts, `-m`:** `aew.engine.custody_ops:worker_argv`
- **Starts, `console-script-argv`:** `aew.dashboard.projections:Projector._search_hit`
- **Starts, `console-script-on-PATH`:** `aew.harness.agentenv:build`, `aew.harness.opencode.lead:tui_env`

### `aew (contained Lead)`

- **Kind:** non_writer
- **Why:** the CLI inside the contained Lead's sandbox (AEW_LEAD_CONTAINED set): its Lead-authenticated commands go through the Lead broker, which holds the credential and the lock, and it reads lock-free, since the sandbox holds no control lock (`.aew/local` is masked) and `.aew` is read-only there
- **Declares itself at:** `aew.cli.main:_main`
- **Starts, `console-script-on-PATH`:** `aew.harness.agentenv:build`, `aew.harness.opencode.lead:tui_env`

### `aew (worker run)`

- **Kind:** non_writer
- **Why:** the CLI inside a worker's harness run (AEW_AGENT_ENDPOINT set): `whoami`, `check run` and `submit` go through the run's bridge, whose supervisor holds the credential and the lock; nothing else in that process may take the lock
- **Declares itself at:** `aew.cli.main:_main`
- **Starts, `console-script-on-PATH`:** `aew.harness.agentenv:build`, `aew.harness.opencode.lead:tui_env`

### `aew dashboard serve`

- **Kind:** non_writer
- **Why:** the dashboard server, long-running and read-only: it reads the store lock-free (dashboard.reader) and serializes its own publication with its endpoint lock, never the control lock
- **Declares itself at:** `aew.cli.main:_main`
- **Starts, `console-script-on-PATH`:** `aew.harness.agentenv:build`, `aew.harness.opencode.lead:tui_env`

### `aew lead mcp`

- **Kind:** non_writer
- **Why:** the Lead's MCP transport: it constructs no engine and forwards every call to the Lead broker, which holds the credential
- **Declares itself at:** `aew.cli.main:_main`
- **Starts, `console-script-argv`:** `aew.harness.opencode.projection:LEAD_MCP_COMMAND`
- **Starts, `console-script-on-PATH`:** `aew.harness.agentenv:build`, `aew.harness.opencode.lead:tui_env`

### `aew.harness.supervisor`

- **Kind:** store_writer
- **Why:** a run's supervisor: holds the run's credential and commits through the engine
- **Declares itself at:** `aew.harness.supervisor:main`
- **Starts, `-m`:** `aew.engine.harness_ops:Harness._spawn_run`

### `aew.stg02.server`

- **Kind:** non_writer
- **Why:** the STG-02 slice's producer: it reads a project's committed state lock-free (dashboard.reader) and writes only its own state directory, never the store
- **Declares itself at:** `aew.stg02.server:main`
- **Starts:** none found
