# Writers

Every path under `.aew` that AEW code writes, and the module and function that writes it. Generated by `python tools/reference.py render`; do not edit. Read from the source with `ast` and run nowhere (`static`): a write is a call of a write primitive whose destination this reading follows to a path under `.aew` (through assignments, constants, `self` attributes, parameters and the functions that build paths). A path is a template: `{}` is a segment computed at run time. `named_by` lists the module-level constants that spell the path exactly. A writer's `mechanism` is `store-transaction` (it stages the file in the control store's transaction, which the store applies under the control lock) or `direct`; `via` names the primitives.

The list is a lower bound. A write whose destination this reading could not place is its own record, below and in [gaps.md](gaps.md), and any of those may write any path here. A call whose `open` mode or `os.open` flags cannot be read is one of those records too (its primitive ends in `?`): whether it writes is not decided. The primitives it reads: `Path.hardlink_to`, `Path.mkdir`, `Path.open`, `Path.rename`, `Path.replace`, `Path.rmdir`, `Path.symlink_to`, `Path.touch`, `Path.unlink`, `Path.write_bytes`, `Path.write_text`, `atomic_write`, `create_exclusive`, `open`, `os.link`, `os.makedirs`, `os.mkdir`, `os.open`, `os.remove`, `os.rename`, `os.replace`, `os.rmdir`, `os.symlink`, `os.truncate`, `os.unlink`, `replace_with_retry`, `session.write`, `shutil.copy`, `shutil.copy2`, `shutil.copyfile`, `shutil.copytree`, `shutil.move`, `shutil.rmtree`, `sqlite3.connect`, `write_file`, `write_temp`. What this reading does not see: a path built in one function and written in another through a value this reading cannot follow (a command-line argument, an environment variable, a callback, a renderer); a primitive called through a conditional expression, `(a if x else b)(path)` (the store's own `write_file` does this); a primitive bound to a local name and called by it; a method named by a computed attribute, `getattr(path, name)(...)`; a write by a subprocess; an opener other than `open` and `Path.open`, such as `codecs.open`; a file kept under `.aew` by `tempfile.NamedTemporaryFile(dir=...)` or `mkstemp(dir=...)`; a `rename` or `replace` whose target is a keyword argument; a store transaction's `write` on a receiver not spelled `session`; a `.open(x)` whose positional argument is not a literal mode, which another API's `.open` also has (a mode in `mode=` that cannot be read is an unresolved write); `chmod`, `os.utime`, `fsync_dir` and other calls that change a file's metadata or durability and not its content (not writes).

## Which entry points reach the writers

A chain of resolved calls from the function where an entry point declares itself (see [entry-points.md](entry-points.md)), so a writer's `entry_points` is a lower bound: a callback, or a call on an object whose class is not evident, is not followed. The CLI's four roles share one declaring function, so a writer it reaches is reached from all four; which role runs a command is decided at run time by arguments and environment, and not here. A command that writes the store in a non-writer role is refused when it opens the control lock (`process_kind.require_writer`); that gate is tested at run time, not proved here.

Writer functions with a store-transaction or direct write placed under `.aew`: 70; reached from at least one entry point: 51.

- `aew` (store_writer): 49 writer functions
- `aew (worker run)` (non_writer): 49 writer functions
- `aew dashboard serve` (non_writer): 49 writer functions
- `aew lead mcp` (non_writer): 49 writer functions
- `aew.harness.supervisor` (store_writer): 7 writer functions
- `aew.stg02.server` (non_writer): 0 writer functions

**Checked:** a writer reached from an entry point whose declaring function declares no store writer (`aew.stg02.server`): none.
**Not checked:** the CLI's non-writer roles share their declaring function with the store writer `aew`, so this reading cannot tell which of the four roles reaches a writer the CLI reaches (a non-writer is not a process that writes nothing: it takes no control lock and may write its own files under `local/`). Cutting the CLI per role needs the parser's subcommand-to-handler mapping for the roles `cli_entry_point` names; that is a decision for the design side.
