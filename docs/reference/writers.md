# Writers

Every path under `.aew` that AEW code writes, and the module and function that writes it. Generated by `python tools/reference.py render`; do not edit. Read from the source with `ast` and run nowhere (`static`): a write is a call of a write primitive whose destination this reading follows to a path under `.aew` (through assignments, constants, `self` attributes, parameters and the functions that build paths). A path is a template: `{}` is a segment computed at run time. `named_by` lists the module-level constants that spell the path exactly. A writer's `mechanism` is `store-transaction` (it stages the file in the control store's transaction, which the store applies under the control lock) or `direct`; `via` names the primitives. The store's apply step writes whatever the transactions staged, so the staging sites are the writers and it is not. One file the commit stages itself, the events sidecar `state/log/{}.events.yaml` (`ControlStore._commit_unprofiled`), has no staging site among the writers: nothing here names what creates it.

The list is a lower bound. A write whose destination this reading could not place is its own record, below and in [gaps.md](gaps.md), and any of those may write any path here. A call whose `open` mode or `os.open` flags cannot be read is one of those records too (its primitive ends in `?`): whether it writes is not decided. The primitives it reads: `Path.hardlink_to`, `Path.mkdir`, `Path.open`, `Path.rename`, `Path.replace`, `Path.rmdir`, `Path.symlink_to`, `Path.touch`, `Path.unlink`, `Path.write_bytes`, `Path.write_text`, `atomic_write`, `create_exclusive`, `open`, `os.link`, `os.makedirs`, `os.mkdir`, `os.open`, `os.remove`, `os.rename`, `os.replace`, `os.rmdir`, `os.symlink`, `os.truncate`, `os.unlink`, `replace_with_retry`, `session.write`, `shutil.copy`, `shutil.copy2`, `shutil.copyfile`, `shutil.copytree`, `shutil.move`, `shutil.rmtree`, `sqlite3.connect`, `write_file`, `write_temp`. What this reading does not see: a path built in one function and written in another through a value this reading cannot follow (a command-line argument, an environment variable, a callback, a renderer); a primitive called through a conditional expression, `(a if x else b)(path)` (the store's own `write_file` does this); a primitive bound to a local name and called by it; a method named by a computed attribute, `getattr(path, name)(...)`; a write by a subprocess; an opener other than `open` and `Path.open`, such as `codecs.open`; a file kept under `.aew` by `tempfile.NamedTemporaryFile(dir=...)` or `mkstemp(dir=...)`; a `rename` or `replace` whose target is a keyword argument; a store transaction's `write` on a receiver not spelled `session`; a `.open(x)` whose positional argument is not a literal mode, which another API's `.open` also has (a mode in `mode=` that cannot be read is an unresolved write); `chmod`, `os.utime`, `fsync_dir` and other calls that change a file's metadata or durability and not its content (not writes); a command handler that calls an engine method by a name held in a variable, `getattr(engine, name)(...)` (the `integrate` commands' handlers, for one): the writers behind it are not attributed to the command's role; a local list that is also grown by `extend`, `+=` or `insert` (read as its literal and its `append`s), a list argument a caller builds that way, and a dict key reassigned after its literal (`unit['record'] = ...`, `unit.update(record=...)`, read as the literal's value): no mark is made for them.

A sibling of a path (`with_name`, `with_suffix`, `with_stem`) is a path of its own when its name is a fixed string, or the path's own name, suffix or stem with a fixed string added (`p.with_name(p.name + ".queue")`). A name made by the process (a process or thread id, a clock, a random value, `tempfile`) is part of the write protocol of its path and is taken as that path, as is an f-string that starts with the path (`f"{path}.tmp"`). Any other name is a write this reading cannot place.

## Which entry points reach the writers

A chain of resolved calls from the function where an entry point declares itself (see [entry-points.md](entry-points.md)), so a writer's `entry_points` is a lower bound: a callback, or a call on an object whose class is not evident, is not followed. The CLI declares its roles in one function and the command decides which runs, so the parser cuts them: the handler a command registers is reached by the role of that command (what `process_kind.cli_entry_point` says of its words), and the calls the CLI's function makes itself, which every command shares, by all of them. The role the environment selects is no command's: the call graph gives it nothing, and a write a non-writer may not make is refused there by `process_kind.require_writer`, a gate tested at run time and not proved here.

A `with` statement's implicit `__enter__` and `__exit__` calls are not followed either, so what a context manager writes is attributed only to the roles that call it by name: the dashboard server takes its own lock file by `with self._lock():` (`aew.dashboard.service:Service.start`), and `local/dashboard/endpoint.lock` and `local/dashboard/endpoint.lock.queue` are listed under `aew` alone. The counts of writer functions reached below are lower bounds.
