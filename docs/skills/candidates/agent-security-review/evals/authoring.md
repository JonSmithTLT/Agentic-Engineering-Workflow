# Authoring and evaluation notes

## Current candidate 0.2.1

This procedure helps a worker assess the scope and enforcement of an agent trust boundary through source and existing defensive evidence.
Project scope, authorized access, and finding disposition come from the
invocation and adopted AEW rules.

The [cases](cases.yaml) contain four synthetic, materializable scenarios
covering owner-check evidence, capability availability, a missing current configuration, and an unrelated editorial task. Use the
[rubric](rubric.md) and the [current source record](sources.md). Supply the
worker payload and pinned runtime files. Keep oracle answers and evaluator
notes with the evaluator. Public cases are development fixtures. A holdout
requires separately authored cases.

Check correct activation, the decisive evidence, supported outcomes, and
honest uncertainty. Give supplied observations, fresh execution if assigned,
and different subject versions separate evidence status. For an effectiveness
comparison, freeze exact inputs and score equivalent baseline and skill-enabled
setups. Record worker outcomes separately from package and materialization
checks. No worker outcomes have been measured for this version.
