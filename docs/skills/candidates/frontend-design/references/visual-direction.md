# Choosing visual direction

Read for an open visual brief or an authorized redesign, not every component edit.

1. **Ground the idea.** Identify the subject, audience, supplied artifacts, and desired tone. Translate tone into decisions: an archival collection might prioritize captions and image comparison; a live operations console might prioritize dense status scanning. These are possibilities, not mandatory genre templates.
2. **Compose before styling.** Sketch the reading order and relative visual weight. Choose where contrast, scale, alignment, or negative space should draw attention. Use actual headline lengths and representative content; a layout that works only with three-word placeholders is unfinished.
3. **Choose a coherent vocabulary.** Define text roles, restrained spacing increments, semantic color roles, borders/surfaces, and consistent image treatment. A system font or an expressive display face can each be correct. Check actual glyph coverage, weights, loading behavior, and fallback before relying on typography. Keep body copy readable and line lengths appropriate to the surface.
4. **Give assets a reason.** Prefer supplied product imagery or relevant material over interchangeable stock decoration. Confirm availability and permitted use. If a defining asset is missing, use an honest placeholder or an alternative composition rather than inventing an endorsement or pretending to reproduce a reference you cannot inspect.
5. **Critique against the brief.** Can a viewer identify the subject, priority, and next action? Does the design remain distinctive when decorative effects are removed? Does its density suit the task? Are repeated motifs helping navigation or merely filling space? Fix the weakest consequential decision rather than adding more accents.

For existing products, observed components and current tokens establish continuity. When references conflict, determine whether they show different variants or an authorized new direction. Do not infer redesign permission from an absent DESIGN.md. Record reusable decisions in an existing project design record when warranted; a one-off change needs no new documentation system.
