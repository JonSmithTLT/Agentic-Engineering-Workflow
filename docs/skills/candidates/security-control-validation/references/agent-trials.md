# Trials involving model decisions

Use only when model variability affects the security claim.

- Freeze the target configuration, model/version where observable, tools, attack fixtures, benign controls and grading rule before comparing defenses. Record unavailable provider details rather than inventing reproducibility.
- Measure protected actions and tool effects where accessible. A text refusal may coexist with a completed side effect; plausible compliance text may coexist with enforced denial. A model judge is a fallible observation, not ground truth about tool execution.
- Predeclare attempts, time and cost limits and retain every result, including errors and inconclusive runs. A broken harness is neither a safe target nor a successful attack. Report valid and invalid denominators separately.
- Reset relevant memory/session state between independent trials; evaluate persistence separately when intended. Group repeated variants from one attack family rather than presenting them as independent coverage of many threats.
- Keep attack discovery separate from evaluation. Freeze discovered cases for regression, then use separately authored cases to test generalization. Do not optimize a defense against a test set and describe that same set as unseen evidence.
- Report observed successes/attempts and uncertainty appropriate to the design. Zero observed successes does not establish zero risk. Compare benign-task success as well as attack outcomes so blanket refusal does not look like an effective usable defense.
