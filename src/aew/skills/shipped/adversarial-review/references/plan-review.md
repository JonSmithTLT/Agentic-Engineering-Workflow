# Reviewing plans and companion inventories

Read when the reviewed subject is a plan rather than an implemented change. Separate present source facts, proposed edits, and evidence claimed for the future design.

1. Pin the supplied plan version, source base, and companion identities. Diff against the actual previously reviewed version first. Verify supplied hashes; if a cited companion differs, report the mismatch before relying on its result. Retain the old cited artifact rather than silently replacing its bytes with a regenerated version.
2. Check referenced symbols and ownership in current source. Mark planned interfaces as proposed. Preserve qualifiers in prior findings and plan obligations; compare the original finding when a summary changes its meaning.
3. Read companion scripts before any run, including imports and side effects. Execute only through a permitted isolated mechanism against the pinned source snapshot; an archive alone is not a sandbox. Parameterize the checkout instead of hard-coding a developer path. Record invocation, output, snapshot, and digest where the plan binds it.
4. Audit the inventory algorithm, not only the final count. Match decoded values and structure as relevant, including bytes literals and constants in each writing position. Validate hand-coded table rules against their owners. Assert distinct keys before inserting into maps; report exclusions and unsupported forms. Counts copied from another inventory are not independent checks.
5. Where plans overlap, join their inventories by the identity the guarantee concerns, not prose similarity. Name one disposition/owner per site or key and report unowned or conflicting rows. Check whether one plan's proposed edit changes the forms or sites the other scan sees. A baseline hash does not certify post-edit coverage; use an isolated simulated edit or explicit analysis of the transformation when appropriate.
6. Assess whether proposed guards close the full reachable class, and whether tests would discriminate the original mechanisms. Report a plan defect as a defect in the proposal; do not claim a runtime reproduction of unimplemented code.

Stop with supported findings and unresolved dependencies in the host review format. If a necessary companion or source version is missing, name precisely which claims cannot be checked while continuing independent parts.
