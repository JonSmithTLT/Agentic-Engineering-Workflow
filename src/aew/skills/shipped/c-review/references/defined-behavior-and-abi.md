# Defined behavior, concurrency and ABI

**Check remaining defined-behavior and boundary assumptions.** Inspect reads newly reachable from a changed path, non-literal format strings used to interpret input, partial-state reads, alignment, aliasing, shifts, pointer arithmetic and lifetime transitions when the path uses them. For synchronization, give a permitted interleaving and the missing ordering; do not infer a race from two accesses without checking locks or ownership. For ABI changes, compare both sides of the actual binary boundary: exported declaration, calling convention, layout, symbol and consumers. Reordering ordinary non-bit-field struct members changes their relative offsets without needing target-specific sizes; check which members existing binaries access. Do not generalize this to overlapping C++ members or bit-fields. A source change is not automatically an ABI break. State whether old binaries must remain usable and which target facts establish an incompatibility.
