# Untrusted input

**Follow the representation that reaches the consumer.** For untrusted input, carry length, encoding, normalization, type and validation result through decode/parse/lookup/use. Check that bounds and allowlists constrain the final representation and operation (SQL, shell, path, URL), including partial, error and resumed paths. For resource exhaustion, give a reachable input and the work or allocation it drives relative to supplied limits. Documented API behaviour is evidence, not invention: a deserializer running code, a client following redirects, a shell interpreting input. Do not invent a network endpoint, parser behavior, deployment limit or exploit primitive to finish the argument. Native memory details can be reviewed with `c-review` when available.
