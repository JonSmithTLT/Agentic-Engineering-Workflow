# AEW frontend behavior contract

Sources: `docs/design-direction.md`, `docs/design/plans/w02-workspace.md`, `docs/design/plans/w03-journal.md`, and accepted API referenced by `docs/c0-approval.json`. Backend owns workflow/authorization/health and persistence. No mutating product actions.

## Canonical UI map

Shared Shell owns a reachable Close navigation action inside the open phone sidebar. Closing restores focus to its header trigger without changing the current route or selection. Native theme selection remains sidebar-owned; browser checks open the sidebar rather than forcing interaction with concealed controls.

Demo Settings uses shared InvestigationTabs, CopyDashboardLink and focusBelowHeader. Fields are read-only data; no Save or catalog action. SET/NULL/ABSENT/withheld/effective facts and completeness retain supplied meaning. Inventory and detail binding are validated before display. Unsupported activities issue no execution detail read. Source/session/scenario/activity changes retire late responses. Profile index is digest-bound, including masked locators; mismatched links never select a replacement profile. Production contains no Settings fixture UI or schemas. Live transport and adoption remain F1b/F1c work.

Overview and the shared header label the supplied health projection as project health. Its status and reasons remain backend-owned; this label neither represents U1/H1 run health nor changes the API's `health` field or vocabulary.

Shared `src/styles.css` owns disclosure boundaries and table scroll frames. Native details/summary interaction, document scrolling and table semantics remain unchanged; expanded content stays visually enclosed. Map Fields owns supplied label/value grouping without reinterpreting values. Each Maps metadata disclosure names its response (overview, selected map, input page, stored maps or comparison). Borders do not imply authority, completeness or a new data scope.

## Explicit raw-history search

Maps uses the shared InvestigationTabs, Pager, SourceStrip, focusBelowHeader, reference-return and navigation allowlist. It bootstraps the project and gates reads on the separately supplied maps capability. The displayed summary follows the 30-second visible cadence and foreground coordinator. Stored maps, exact root detail, input pages and differences are navigation/manual-only, excluded from interval, foreground and revision reconciliation. Activity departure cancels/removes its query and validator; page bodies replace rather than accumulate. Root and A/B bindings are checked before caching. Ordinary refresh failures retain explicitly stale valid data; refusal clears inaccessible representations. Map revision remains separate from control revision.

Map identities accept full SHA-256 roots and full commit object IDs only; unknown/repeated presentation values are refused before Maps reads. Identity forms own associated noValidate errors and first-invalid focus through focusBelowHeader. Both comparison roots remain explicit; draft edits do not relabel a supplied result. Loaded-page absence is distinct from unavailability. Supplied currentness, drops, omissions and beyond-cap changes remain visible; no browser map generation, test execution, inferred acceptance or global completeness. Provenance discloses metadata. Architecture follows only its supplied Evidence reference. Back restores the originating loaded root or architecture link through reference-return; copy/reload preserves activity, root, section, cursor, operands and explicit against commit.

History exposes Raw history search only when its separately supplied capability is present. A direct link while absent explains that the route is not offered and issues no search read. Available search bootstraps the project first. Unavailable/unknown capability states remain supplied results. Losing the capability retires queries, validators, draft and result even when another page is displayed.

HistorySearchSession owns one in-memory draft and submitted representation, scoped by the accepted reader's contract/project/session identity. Only explicit Search or Retry reads. Mount, editing, reload, foreground, reconnect, reconciliation and Back never search. This is a documented override of default debounce and URL-persisted search: operator terms may be sensitive and the bounded backend read can advance derived indexing. Clear cancels pending work, removes owned cache/validator data, resets the form and focuses Term 1. IME composition cannot submit. Pending submission prevents duplicates; navigation cancels a pending read while keeping prior valid Back results. New submissions replace the old query, ordinary retry failure retains marked valid data, refusal removes inaccessible data, and late responses cannot populate a cleared/replacement scope. No search terms enter browser URLs or localStorage.

Native term inputs, checkboxes/selects and UTC text fields retain OS interaction. The app owns noValidate errors, associated help/error text and first-invalid focus. Separate literal phrase rows preserve spaces without browser tokenization. Results explicitly name the submitted terms, so subsequent draft edits cannot mislabel them. Coverage and reasons remain distinct from no hits; labels and supplied fences frame each plain-text snippet. No Markdown, executable HTML or remote snippet links are rendered. Expansion follows only supplied supported History/Evidence references; copied argv must match the shared read-only history-show allowlist. SourceStrip metadata is disclosed with refresh failure still visible. Browser Back restores the originating reference through the shared reference-return owner; a reload starts an empty search.

## Journal interaction/state ledger

Automatic foreground revalidation is owned by `client/queries.installVisibility`. Companion visible/focus callbacks share each query's pending foreground read. A new hidden/blur episode permits another wake to supersede old reads; manual refresh and session retirement keep their cancellation behavior. New/replacement queries remain eligible, settled reads do not suppress later refresh, and fixed/manual-only or concealed projections keep their exclusions. There is no debounce, inferred expiry or backend freshness policy.

Demo startup loads the initially requested preview screen after fixture initialization; other investigation screens load on route demand. Shared `components/DeferredScreen` owns the later screen's announced loading state and contained failure/reload result; `api/mock/DeferredScreen` reexports that boundary for existing previews. Production Raw history search uses the same boundary on route demand. The shell and developer toolbar remain available. Requests disclosure loads no Playground UI; Scenarios/Contract explicitly request it. A failed chunk offers a full reload of the current allowlisted link rather than changing selection or inventing data. The packaged baseline is unchanged.

Select opens in place and preserves results; close returns focus to entry or heading. Selected ID stays visible above both panes; mobile Results/Detail buttons show the current pressed state. Following a Journal reference focuses its ID/title heading below the sticky header. Filter/page changes preserve explicit selection with an out-of-results notice; filter change resets cursor. Stream/table toggles keep cursor/selection. Native selects use their supplied option identities. Tabs implement arrow/Home/End navigation. Narrow pane switches stop concealed detail polling and revalidate when revealed. Metadata, type legend and graph disclosures are non-modal. Loadable graph nodes are marked not expanded until loaded; unavailable references stay terminal.

Initial reads show loading or an inline error/retry. Background failure retains marked valid data. 401/403 clears inaccessible data and validator. Session/case changes retire responses, caches and graph state. Empty/no-results explain recovery. Unknown values retain raw warnings. Missing explanation does not derive meaning from neighboring fields.

Desktop selection from a Journal results link preserves focus on that link and its sequential Tab position; the selected-ID status announces selection politely. Phone results selection focuses the replacing detail. Navigation originating inside detail, graph references or initial deep links focuses the available ID/title heading. The origin is captured before the asynchronous read, so refreshes do not move focus.

No edit/create/delete, credential handling, billing, legal workflow or data-entry form is introduced by W03. Toast/dialog/date/form capabilities are not applicable. Future capabilities require explicit ownership rather than screen-local substitutes.

## Comparison and packet interaction/state ledger

W04 source choice is explicit; accepted invocation identity may seed A but never chooses a snapshot or counterpart by similarity/time/success. Changing one side preserves the other; Swap exchanges both source and run choices. Below1024px paired values stack A/B per field. Missing or partial data is Unavailable, never Same/Different. Structural differences are presentation only.

`InvestigationTabs` owns W04 keyboard tab behavior; native selects and `Pager` retain their existing owners. `focusBelowHeader` owns W04 heading focus. Packet models, receipts, bindings and `PacketInspector` are independent of comparison; future Journal/retrieval consumers may reuse them without inferred semantic relations. SourceStrip's optional readSnapshot identifies the actual preview reader without changing accepted provenance.

Opening a packet replaces comparison and stops hidden intervals. Back restores comparison state/scroll/origin focus after the route commits; direct inspector reload resolves only its owning source. Current visible sources poll10seconds; fixed sources and packet pages have no intervals. Refusal clears all representations/queries owned by the affected preview reader, preserving the other side and accepted scopes. Validation occurs before payload caching, including identity/snapshot and packet/receipt bindings. Ordinary failures retain marked valid prior data. No raw prompt/credential/artifact bodies or inferred receipt claims.

Copy links allowlist explicit source/run/tab/filter/packet/page/case presentation state. Opaque demo cursors are filter/dataset/project/revision-bound and reloadable, not authorization credentials. Unsupported historical links stop preview reads. Source chooser payloads contain metadata only, so denied details cannot leak through collection payloads. Budget values and selection explanations are supplied; the browser never fabricates token accounting or selection reasons.

Fixed snapshots are manual-only after their initial read: focus, visibility, revision reconciliation, and returning from the inspector do not refresh their cached payload. Closing or completing a source chooser restores focus to its Change A/B control. Packet comparisons use the same run-filtered supplied associations that are rendered.

W04 review fixes: the source chooser keeps native table semantics and stacks labeled cells on phone; each row shows only a bounded supplied summary, with explicit excerpt truncation and no denied summary. Returning from an inspector restores the originating packet control after layout commits and scrolls it below the sticky header. Reference navigation stores only scroll/reference presentation state in the departing history entry so browser Back can restore the originating Journal link. The Receipts tab explicitly labels missing stages as unknown in this projection.

W05 fixed source metadata, artifact lists and excerpt pages are manual-only with no concealed intervals/prefetch. Unicode bidi/invisible/ANSI controls are visible markers, while hashing and citations identify original UTF-8 bytes. Full artifact digest is supplied, not verified. Missing material does not establish absence; outcomes/excerpts do not establish causation. M6 Capture & Admission references Evidence and never replaces ownership.
