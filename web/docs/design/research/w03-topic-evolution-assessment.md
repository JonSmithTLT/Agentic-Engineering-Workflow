# W03 seams for later subject and knowledge exploration

Assessment requested by the designer on2026-10-03. This is future-design guidance, not W03 scope expansion, Topic schema adoption, or permission to infer grouping in the browser.

| Future capability | Current seam | Required future work |
|---|---|---|
| Supplied Subject/Topic facet | JournalResults builds explicit server filters and renders supplied facet options; filtering remains in JournalProjector. Selection is independent of the current results. | Accept a versioned field/filter/facet contract, identity/null semantics and ordering/cursor scopes. Add its explicit query and copy-link allowlist entries. Do not overload component or derive subjects from titles/paths. No pane redesign is needed. |
| Evolution edges such as refines | Journal relations carry a supplied relation string and target. inspectJournal adapts them into bounded RelationsExplorer with field-level source attribution. Unknown target kinds remain terminal. | A supplied refines token can already be shown as a relation; it has no inferred meaning. Relation-level reason/source/provenance is **not** in preview0.1.0 and requires a new versioned schema plus a typed adapter/presentation extension. Keep source field identity separate from future semantic relation type; do not parse displayed field strings to decide meaning. |
| Related knowledge for a subject | The results/selection split, read policy and per-contract scoped cache permit another supplied collection projection with the same inspector. | Backend owns membership, permissions, pagination, revision and completeness. Use the existing typed read-context and reader adapter boundary, with a distinct route/schema/digest as appropriate. A bounded origin graph is not a retrieval engine or complete topical index. |
| Derived versus curated membership | Current UI labels source and browser observations separately and displays explicit partiality. | Supply grouping method and explicit/curated membership metadata; label the collection and each relevant membership source. Derived grouping is a projection, not a new authority object. Promote a durable concept only through separate design/evaluation. |

No generic facet framework or Topic field is added now. Preserving the existing filter builder, typed read policy, inspectJournal adapter and RelationReader boundaries is sufficient. The main limitation to address before W07 is relation-level metadata: the current explorer attributes edges to a record/field and explicitly says no edge-specific reason or receipt was supplied. Keep that truthful until the wire model supplies more.

Browser code must not infer topics, membership, supersession, contradiction, refinement, acceptance or benefit. Stable component/symbol/capability subject anchors, grouping provenance, relation metadata and any authoritative concept lifecycle remain backend-owned design questions. W03 continues component/type filtering and supplied relations only.
