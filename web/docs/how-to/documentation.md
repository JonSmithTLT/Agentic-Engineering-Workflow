# Documentation policy

Organize by what the reader needs: `how-to/` contains actionable procedures, `concepts/` explains architecture and boundaries, and `reference/` records facts and inventories. `design/` contains plans, proposals and research; `reviews/` holds active review packets; `archive/` preserves completed milestone and core history. This adapts [Diátaxis](https://diataxis.fr/) and [Read the Docs structure guidance](https://docs.readthedocs.com/platform/stable/explanation/documentation-structure.html) to the project's review workflow. Plain-text documentation, Git review and automated checks follow [Docs as Code](https://www.writethedocs.org/guide/docs-as-code/).

Every new document needs a descriptive title, a clear purpose, and an index entry. Use repository-relative references in committed prose and relative Markdown links for navigation. Include date/source identity for status and reviews. Keep current instructions in guides; link the archive for historical reasoning. Create a tutorial only when there is a real learning task, not an empty category.

Move completed reports and their entire evidence bundles together. Preserve logs, images, JSON, checksum files, signed plans, approval records and canonical artifacts byte-for-byte. An archive is not a new acceptance decision. For unsigned narrative reports, relocation may repair navigation links only; record the change in the catalog. Historical inline command paths remain historical and can be resolved through the catalog. Never fabricate missing evidence.

`reference/documents.json` maps old paths to current paths and pins retained bytes. Register newly published docs in `new_documents`; keep private/untracked handoffs out. Run `npm run check:docs` before committing. It checks catalog coverage of tracked docs, protected hashes, and local Markdown file links; it does not validate remote URLs or heading anchors. The offline copied source uses the same explicit catalog without requiring Git metadata.

Keep the three root C0 exceptions, signed `design/plans/` documents, runtime-imported preview artifacts/manifests, and active review bundles in their pinned locations. If an actual contract path must change, obtain coordinated contract acceptance rather than treating it as housekeeping. Register/link a new milestone archive when it closes; retain a rolling [status page](../reference/status.md) rather than revising old approvals.
