# Activity: AEW skill feedback

Author field report, not a controlled comparison or human-usability study. Only the AEW candidates were used: frontend-design 0.3.0 (`b8dc97fa0d8ea367c2df190b8f54559841588980fc6c5ea56cadeb3546ecbb11`) and test-design 0.3.0 (`83922d560d746b50077ae76ce5bddcff2f2a03eb6ced4f78e44b3c2f4922aab7`). Read-heavy, asynchronous lifecycle and conditional TDD references were read; project design/API/test rules remain the owners.

## What helped

Frontend-design's early runtime check reused the pinned offline builder rather than trying Windows native dependencies again. Read-heavy guidance kept existing transport identity/refusal/stale behavior and separated manual pinned pages from mutable latest data. Task-first hierarchy retained IDs, UTC times and supplied reasons, with explicit absent destinations instead of invented routes. Variation checks prompted a page-replacement heading/focus behavior so phone paging does not leave the reader at the bottom of a new page.

Test-design supplied an independent oracle: the accepted Activity record and cursor interface plus the approved bounded presentation policy. Cases target accumulation, unsupported destinations, unsafe reason rendering, capability refusal, duplicate cursors, stale/refused refresh and prohibited automatic reads. Tests cross the real query/transport orchestration boundary; the external projection source is controlled. Fake timers and foreground events establish read-policy checks without sleeps. No production expected values are generated by calling its renderer.

The initial red is honestly a missing new page interface: the test module could not import Activity and collected zero tests. It is not an executed behavioral assertion or historical regression reproduction. After implementation, tests exercise actual rendering and paging. Initial test-observation defects included matching a metadata timestamp outside activity rows and expecting a bare capability explanation instead of its supplied reason code. Those were corrected from the schema/UI owner, not by weakening product behavior. A test-selector typing error and non-fail-fast development wrapper were also retained and corrected; later focused typecheck/lint/tests explicitly pass together.

## Improvements, noise and remaining evidence

Both skills are proportionate and respect host rules. The read-heavy reference usefully avoids universal bans on prefetch or universal cache policy. Conditional TDD avoids deleting working code. No new test dependency, coverage target or contrived editorial red/green cycle was imposed.

One useful refinement: explicitly distinguish an anticipated missing-interface suite-load failure from an assertion-level red in the handoff. Another: emphasize scoping observations to their semantic owner when metadata or disclosed warnings repeat elsewhere on the page. The existing text already supports both practices; these would make them easier to apply.

Marketing examples are low-value for this operational slice but small enough to ignore without workflow noise. No conflict with the dashboard contracts or offline gate. I would use both again. No additional skill was necessary. Rendered inspection, negative-control sensitivity, exact-source freeze and independent-review outcomes belong in the factual checkpoint; this feedback does not claim them before they occur.

## Context feedback

The integration audit correctly separates existing routes from new Engine authority. A useful standing input is the route's paging/currentness policy: a cursor window and the latest first window must not be conflated. Demo adapters also need reloadable cursor fixtures to validate copied links; success in one in-memory session is insufficient. Unknown subjects need explicit unavailable destinations, not browser inference. Private research plans are coordination input, not an authoritative backlog.
